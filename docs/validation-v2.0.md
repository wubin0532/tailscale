# v2.0 验证记录

测试日期：2026-10-09。核心固定为官方稳定 `1.104.1`，插件 `v2.0`，IPK `2.0.0-1`，APK `2.0.0-r1`。按维护者最新要求恢复卡片式美化，所有配置与说明直接展开；核心采用官方文件加 UPX 5.2.1 压缩，不做精简编译。

## 已完成的候选验证

- 55 项 Python 后端测试、18 项前端测试通过。覆盖刷新与 Ping 交错、离线节点、请求错误、坏 JSON、CLI 非零退出、锁并发与异常退出、失效快照、控制恢复、路由冲突、防火墙保留与回滚。
- 四种架构的两份核心均经过官方归档 SHA-256 校验、UPX 完整性测试，以及解压后与官方文件逐字节比较。四个本地 IPK 的版本、核心内容、root 属主、可执行权限和配置 0600 已核验。
- 浏览器检查 360、390、768、1440px，浅色和深色；四页统一宽度，手机无横向溢出，按钮触控高度至少 44px。包括搜索、在线筛选、Ping 跨刷新保留、日志暂停及配置说明。
- ARM64 LibWrt 真机重新授权的新身份已保留。核心、RPC 与页面均返回相同四个对端，包含 Home 和离线节点。Home 直连、VPS 中继可达，家庭网关 ICMP/HTTP、WAN HTTPS 已通过。
- 使用真机 BusyBox、jsonfilter 和 jshn 对隔离的 1.2 MB 有效状态进行了 RPC 验证，成功状态、在线状态、设备名及兼容的 raw 字符串均正确。

## 审查修复

- 修复 Argon 全局 header 样式覆盖插件标题、flex 容器按内容收缩、Boolean disabled 属性误禁用按钮。
- Ping 状态按稳定 ID 保存；状态失败不会误报“没有设备”，空闲节点不会直接标为中继。
- 状态、服务和 CLI 操作采用 flock 文件锁，不删除锁文件；异常退出不留下永久目录锁。CLI 子进程关闭锁 FD，后台登录 worker 保留锁直到结束。
- LocalAPI 通过有超时的 Unix socket 访问，原子私有快照最长 5 秒，不缓存完整敏感偏好。大型 JSON 经文件/stdin 处理，raw 以流式方式编码，避免 argv/env 长度限制。
- 瞬时快照失败不再被路由 watcher 当成控制恢复，避免重复启动 CLI 应用配置；超时操作采用 TERM 后 KILL。
- 修复 LuCI `cidr` 校验修改内部 value 为前缀长度，导致后续自定义校验误拒绝合法网段的问题。真实页面确认 IPv4、IPv6、`/32`、`/128`、`/0` 可输入；非网络地址与越界前缀仍拒绝。NAT IPv4 地址/网段、端口及范围通过；Headscale 无效主机/端口和出口无效 IP 不再放行。仅编辑临时表单测试，未应用这些测试配置。

- Ping 明确使用 `--until-direct=false` 检查可达性。VPS 在 DERP 中继上收到 pong 时成功；真实离线节点仍返回非零退出码和超时错误，不把无法直连误报为无法访问。

## 查询开销与内存

同一官方核心、相同配置、UPX 安装，在 ARM64 真机分别执行 5 次 CLI 状态查询和插件 RPC 查询。CLI 耗时中位数 1.09 秒、峰值 RSS 中位数 22696 KiB；RPC 为 0.13 秒、1480 KiB。RPC 以直接运行后端方式计量，包含子进程，未将 ubus 客户端的内存当作后端内存。

三个场景各采样 30 秒：不增加测试查询、每 5 秒查询状态、连续检测 Home。守护进程 RSS 分别为 16272–19872、18276–20436、20080–21748 KiB；VmSwap 分别为 14840–17928、14936–16500、14232–15696 KiB。前两场景未采到 Go CLI，检测场景最多采到一个。用户自己的浏览器标签可能仍在刷新，所以第一场景不声称所有页面关闭。采样可能遗漏很短的进程。

ARM64 两份官方二进制从约 69.08 MiB 压缩到 29.25 MiB，节约约 58% 安装存储；UPX 完整性和解压逐字节比较通过。此数字不表示运行内存下降。

## 验证边界

目前真机为 ARM64、opkg、fw4。其它三种架构、APK 和完整 OpenWrt SDK 未在真机运行。交付产物由 main 的 CI 构建；安装其中的 ARM64 IPK，核对交付文件与测试文件的校验和。按维护者要求不创建新分支或标签，GitHub Actions 保存安装包，不创建 GitHub Release。

真机内核没有 smaps/smaps_rollup，不能报告 PSS。RSS 和 VmSwap 分开记录，VSZ 不作为实际内存。查询内存改进不等于守护进程内存下降；UPX 主要节约存储。原旧身份缺少 Home 的根因未获证实，不将新身份成功归因于单一页面修复。

测试期间发现路由器约 16:33 发生过一次整机重启，原因未确认。当前可读日志未发现 OOM/panic，内核无 pstore；恢复后新身份、Home、VPS、家庭网关与 WAN 均正常。不能据此证明或排除早先重启的原因。
